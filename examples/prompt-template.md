# 提示词模板

把下面任一段直接发给你正在使用的 AI 助手即可。MCP 会按「先出确认清单 → 你确认 → 才真正花钱送审」两阶段执行。

---

## 0. 最简版（参数交给助手定）

```
用 cross-model-reviewer 审校这份产物，artifact_type=doc：
<粘贴内容 / 或写「文件：/绝对/路径/xxx.md」>

先出确认清单给我看，我确认后再送审。
```

默认走 `deepseek-v4-flash` + `max_tokens=16384` + `reasoning_effort=medium`。适合临时审一段文字、初筛。

---

## 1. 标准单审（推荐日常使用）

```
用 cross-model-reviewer 帮我做独立校审，先出确认清单，我确认后再送审。

【产物】文件：/绝对/路径/xxx.md          ← 长文档只给路径；短内容可直接粘贴
【类型】doc
【边界条件与验收标准】（最重要，请认真写）
- 主题/范围：……
- 硬性指标：……（精度、性能、字数上限、合规要求）
- 必须满足的假设：……
【侧重维度】数值稳定性,边界条件,指标可复核性
【审校模型】zhipu:glm-5.3-flash
【参数】max_tokens=16384，reasoning_effort=low
【报告落盘到】/绝对/路径/审校记录/
```

只给 **【产物】+【边界条件与验收标准】** 就够，其余助手会按实测稳妥值配好并列给你改。

> **【边界条件与验收标准】是决定审校质量的最大变量**——它把审校从"这样写对不对"提升到"这是不是你要的东西"，也是仲裁者对齐的依据。

## 2. 重型双审（重要产物 / 定稿前）

```
用 cross-model-reviewer 对这份产物做跨厂商并发双审 + 仲裁合并。

【产物】文件：/绝对/路径/xxx.md
【边界条件与验收标准】
- ……
【侧重维度】……
【参数】max_tokens=16384，reasoning_effort=low

先 dry_run 给我看配置清单和预估耗时，我确认后再正式提交；
完成后自动把报告落盘到 /绝对/路径/审校记录/。
```

**为什么要先 dry_run**：双审要调 3 个模型。实测 237 字符文档、低档思考下，两位审校者并发只要 18s，但**仲裁独占 116s**，总墙钟 135s。先看估算再决定值不值得跑。

**只要两份意见、不要合并结论**：加一句「`arbitrate=none`，不仲裁」。

## 3. 参数速查

| 参数 | 填什么 | 说明 |
|---|---|---|
| 产物 | `content` 直接粘 / `content_file` 给绝对路径 | **长文档一律用文件路径**，避免内联超长文本 |
| 类型 | `doc` 或 `code` | |
| 边界条件 | 自由条目列表 | 见上方提示，**别省** |
| 侧重维度 | 逗号分隔 | 如「数值稳定性,边界条件」 |
| 审校模型 | 见下方选模型 | 不写则用默认模型 |
| `max_tokens` | 短文档 8192 起；长文档 16384~32768 | 默认 16384。**GLM 强制思考，给太小会返回空正文** |
| `reasoning_effort` | `low` / `medium` / `high` / `max` | 默认 `medium`。嫌慢说「降到 low」 |
| `use_cache` | 默认开 | 内容+模型+参数全同则复用上次结果、不重复计费。要「重新审一次别看旧结果」就说 `use_cache=false` |
| `report_path` | 目录或 .md 路径 | 完成后自动落盘；不写也能事后用 `export_review` 导出 |

### 选模型

| 用途 | 建议 |
|---|---|
| 日常快速审 | DeepSeek 系 flash 档 / 智谱 flashx 档 |
| 复杂数学模型、专利交底书 | 深推理档（如 `deepseek-v4-pro`）+ `reasoning_effort=high`、`max_tokens>=32768` |
| 深度审校、愿意等 | 旗舰档（如 `glm-5.3`，最慢） |
| 需要**独立性** | **换厂商**：产出自 DeepSeek 就用智谱审，反之亦然 |

---

## 4. 常见坑

- **智谱不支持 `medium`**：传了会 HTTP 400（code 1210）。脚本已自动映射为 `high`；想快就显式说 `reasoning_effort=low`。
- **GLM 的 `low` 几乎不思考**：实测 `reasoning_tokens=0`。要它真动脑子至少给 `high`；但它极快（133 字符 6.7s），适合初筛。
- **两厂商命中集互补**：一方擅长挑**硬错误**（符号丢失、模型不完备、约束违规），另一方擅长挑**符号层完备性**（未定义量、悬空变量、计数遗漏）。**跨厂商换审不是重复劳动。**

## 5. 常用追问短句

| 你想干什么 | 直接说 |
|---|---|
| 看进度 | 「现在到哪一步了」/「查一下 task-0008」 |
| 找回之前的结果 | 「列出最近的审校任务」 |
| 把结果导出成报告 | 「把这次的审校导出成 Markdown 报告」 |
| 换更严的模型重审 | 「换 glm-5.3、思考强度 high，重新审一遍（别用缓存）」 |
| 缩短等待 | 「思考强度降到 low」 |
| 只看各自意见 | 「`arbitrate=none`，不要合并结论」 |

---

## 6. 使用须知

1. **参数不会弹窗**：`max_tokens` / `reasoning_effort` 由助手在构造调用时决定，你默认看不到提示——所以助手**必须**在确认清单里显式列出模型、`max_tokens`、`reasoning_effort` 三项及其来源与推荐值，你直接说要改哪个就行。
2. **两阶段确认**：第一步只打包请求、**不调用模型、不花钱**；你确认后第二步才真正送审。确认了什么就送审什么。
3. **异步执行**：送审后秒回任务号，审校在后台跑，可随时查进度（含实时字符数）。
4. **报告可归档**：`report_path` 写完即落盘，也可事后 `export_review` 补导出，含分级问题表（blocker/major/minor）、分歧点与原始 JSON。
